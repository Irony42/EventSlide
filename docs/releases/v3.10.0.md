## GitHub release: body

> **EventSlide 3.10 fixes about fifteen bugs found by a global review, keeps a guest's photo when the server
> runs out of disk, and makes Safari and iPhone reliable again.**
>
> - **A guest's photo is kept**, not deleted from the phone's outbox, when the server's disk or memory is full
>   (new error code `image.renderUnavailable`) or when a quota a host can raise refuses it.
> - **Safari and iPhone**: no more "this page has expired" on a second upload (WebKit CSRF token race, fixed on
>   the server and in the client), and the aurora background no longer drops the frame rate to 2-3 a second.
> - **Guests and hosts**: a name typed while a scanned code resolves is kept, a stuck request ends instead of
>   hanging, the moderation console no longer hangs or fails silently, the `j` and `p` shortcuts work right after
>   a message appears, and logo and venue photo uploads survive a slow Wi-Fi (10-minute ceiling).
> - **Operators**: four per-account hourly limits are now settings (`INVITATION_RATE_LIMIT_PER_HOUR`,
>   `VENUE_PHOTO_RATE_LIMIT_PER_HOUR`, `BOOK_REQUEST_RATE_LIMIT_PER_HOUR`, `LOGO_RATE_LIMIT_PER_HOUR`, same
>   defaults); `npm run purge` does the whole retention sweep; `purge --dry-run` and `migrate --status` create
>   nothing; a live backup survives a vanishing media file.
> - **Under the hood**: dependency bumps (`npm audit` clean), a sharded, containerised end to end CI with a
>   quarantine for flaky tests, deterministic server and web tests, and a code base split into smaller parts.
>
> **This is a minor release and breaks nothing.** No migration (the last is still 026), nothing to change before
> upgrading: pull the image and restart. Two behaviour changes are worth a read: a refused photo that a host
> could unblock now stays in the guest's outbox, and logo and venue photo uploads have a 10-minute ceiling. See
> the [CHANGELOG](https://github.com/Irony42/EventSlide/blob/v3.10.0/CHANGELOG.md).
