# v3.0.0: drafts of what is posted with the release

Two texts for the maintainer to paste when `v3.0.0` is tagged: the body of the GitHub release,
and a GitHub Discussion. **These texts have not been posted.** No `v3.0.0` tag, release or
discussion exists yet, and creating them is the maintainer's decision. Delete this file once
they are out.

Both announce the licence and, because this is a major, point at what it breaks. Nothing else.
The full list of changes is the [CHANGELOG](../../CHANGELOG.md), the order in which to upgrade is
[Upgrading to 3.0](../UPGRADING.md#upgrading-to-30), and the case-by-case answers about the
licence are in the [licensing FAQ](../LICENSING-FAQ.md).

`v2.1.0` and the tag `gpl-final` already exist. They are the last GPL-3.0 release and the last
GPL-3.0 commit, and nothing here creates or moves either of them.

## Before posting

1. `CHANGELOG.md` lists every pull request merged after #128 and before the tag (see
   `git log --first-parent`), and its date is the day of the tag.
2. `docker compose config` accepts `compose.yaml`: its `env_file` uses the long form with
   `required: false`, which needs Docker Compose 2.24 or later, and no one has run it yet.
3. `git ls-remote --tags origin` lists `gpl-final` (cut on
   `5c2607380ebb18045a14cae979bb54e6fa2def76`), `v2.0.0` and `v2.1.0`. Leave them alone.
4. Create `v3.0.0` on the commit that carries `package.json` at `3.0.0` and push it. Until it
   exists, the footer link of every unmodified copy and the `blob/v3.0.0/` links below are a 404.
5. `git ls-remote --tags origin` shows `v3.0.0` too, and
   `https://github.com/Irony42/EventSlide/tree/v3.0.0` answers 200.

## GitHub release: body

> **EventSlide is now licensed under AGPL-3.0-only.** `v3.0.0` is the first release under it. `v2.1.0` is the last one under the GPL-3.0.
>
> **If you run EventSlide without modifying it, nothing new is asked of you.** No notice, no
> registration, nothing to publish. Your guests and hosts will see a small "Source code
> (AGPL-3.0)" link in the footer of the guest and host screens, in their language. It points
> at the source of the version you run, and it cannot be switched off.
>
> **If you modify it and let other people use your version over a network**, the AGPL
> (section 13) asks you to offer them the source of your version. Publish it, and set
> `SOURCE_CODE_URL` to where it is.
>
> **Nothing published before is relicensed.** Every commit up to and including
> `5c2607380ebb18045a14cae979bb54e6fa2def76`, the tag `gpl-final`, stays available under
> GPL-3.0 for good, and so do the releases `v2.0.0` and `v2.1.0`.
>
> Questions, case by case (unmodified, modified, forked):
> [docs/LICENSING-FAQ.md](https://github.com/Irony42/EventSlide/blob/v3.0.0/docs/LICENSING-FAQ.md).
>
> **This is a major release, and it breaks things.** Before you upgrade, read the `BREAKING`
> section of the [CHANGELOG](https://github.com/Irony42/EventSlide/blob/v3.0.0/CHANGELOG.md)
> and [Upgrading to 3.0](https://github.com/Irony42/EventSlide/blob/v3.0.0/docs/UPGRADING.md#upgrading-to-30),
> and back up with the version you run now. In particular, `compose.yaml` now reads your
> `.env`, and a value that does not fit one of the new settings stops the boot and names it.

## GitHub Discussion

Category: Announcements (pinned). Title: **EventSlide 3.0 is AGPL-3.0-only: what changes for
you**

> `v3.0.0` changes EventSlide's licence from GPL-3.0 to **AGPL-3.0-only**. This post says what
> that means if you run it yourself.
>
> **Why.** The GPL asks you to share the source when you hand a copy of a modified program to
> someone. It says nothing about running a modified copy on a server for other people, because
> then nobody receives a copy: someone could change EventSlide, run it for the public and never
> publish a line. The AGPL closes that gap with one extra clause, section 13. It does not take
> anything away from the people who run EventSlide as it is.
>
> **If you build and run a tagged release without modifying it:** nothing new is asked of you.
> You owe nothing. Your guests and hosts will see a small "Source code (AGPL-3.0)" link in the
> footer of the guest and host screens, in their language. It points at the source of the
> version you run, and it cannot be switched off.
>
> **If you modify it and other people use your version over a network** (your event guests
> count): offer them your source. Publish it, and set `SOURCE_CODE_URL` to that page. The link
> in the footer and `GET /api/about` then offer your version instead of ours.
>
> **If you fork it:** your fork is AGPL-3.0-only too. Point `SOURCE_CODE_URL` at it.
>
> **Older versions.** Nothing published before the change is relicensed. `v2.1.0` is the last
> release under the GPL-3.0, and its commit, `5c2607380ebb18045a14cae979bb54e6fa2def76`, is the
> last GPL commit: it is recorded in `.github/gpl-boundary`, and the tag `gpl-final` is cut on
> it. To know which licence a build is under, read the `LICENSE` file at its commit.
>
> **The licence change removes nothing.** It takes no feature out of EventSlide and puts none
> behind anything. 3.0 is a major release for other reasons, and they are listed under `BREAKING`
> in the [CHANGELOG](https://github.com/Irony42/EventSlide/blob/v3.0.0/CHANGELOG.md): read it,
> and [Upgrading to 3.0](https://github.com/Irony42/EventSlide/blob/v3.0.0/docs/UPGRADING.md#upgrading-to-30),
> before you upgrade.
>
> The [licensing FAQ](https://github.com/Irony42/EventSlide/blob/v3.0.0/docs/LICENSING-FAQ.md)
> covers each case. This is not legal advice. If your situation is not in it, ask here.
